02
The gap

Three layers shipped. The fourth was never built.

x402 settles machine payments in milliseconds and finally. Once settlement confirms there is no chargeback path, no dispute window and no pull back. That is by design: a push payment with no reversal is precisely what lets machines transact without accounts or credit relationships.

How it works

No consensus in the paid path

Five steps, one settling transaction

Call

The agent pays and receives the response immediately. No consensus in this path, no latency added.

Funds enter escrow, not the seller balance. The settlement window runs.

The agent posts a bond sized to the cost of judgment and opens a case. No human is involved.

Validators receive three frozen strings and answer one question independently. Nothing is read from the live internet.

Two sets, always together

The first eighteen cases are the set the question was written against, committed in b50757f one commit before the judgment contract existed. The three held out cases were committed alone in 04ca928, with the runner unable to read the file at that commit, so their answers are provably fixed before the measurement. They were chosen to probe the weakness the first set exposed rather than to raise the score, which is why the second figure is the lower one.

The one miss in the first set is case 12, where three named venues were promised and three different venues were used. The judge ruled not honored and gave the same reason three times. The answer key says unclear because the promise never settles whether the count or the names govern. It is counted as a miss.

Run it yourself

The clerk runs the same eighteen cases against the same prompt in your browser and scores itself. A browser run is an indication, not the consensus number above.

A dispute layer whose reliability has not been measured is a claim, not infrastructure.

07
What it is not

Three limits, each with its reason

Not sub cent yet

Judgment costs about one dollar per case, so the first version targets payments above that line. Session batching is the route below it.

Not an adoption driver today

Agents fail at the payment step for want of funded wallets, not for fear of being cheated. This matters once wallets are routine and an agent must choose between two endpoints that will both take its money.

Not perfect judgment

A vague promise produces a vague verdict, and the system says so through the unclear outcome rather than performing confidence it has not earned.

A refund system in which the merchant selects the judge is a refund policy. It is not a dispute right.

Component sheet

Eight components, every state

The handback list from 10.6 is at the bottom of this sheet: which components read live chain data, and which are static.

ButtonGroup
Horizontal, one selected

Related controls sit in one unit rather than as loose buttons: no gap, a single shared hairline between neighbours, square corners throughout. The selected item carries a light fill and full strength ink; the rest stay at secondary ink until hover.

VerdictPill
4 states
Honored Not honored Unclear Pending

Cyan carries the resolved pair, filled for honored and outlined for not honored. Unclear is dashed and neutral on purpose: it is neither success nor failure, and collapsing it into either would make the system look more certain than it is.

StatusLegend
Pending Submitted, no decision recorded yet.
Accepted The committee agreed on the receipt. Not the same as success.
Finalized The appeal window closed with no valid appeal remaining.

Always visible above the table. Accepted and finalized never share a treatment.
